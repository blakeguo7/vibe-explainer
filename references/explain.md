# 讲解设计：一句字幕出来时，屏上拿什么让观众懂

这一份和外观无关：不管片子长什么样，讲解的方法都一样。
第一节讲"讲解"和"配图"的区别；第二到四节是方法；第五节是分镜表的格式和一个完整的例子。

## 一、讲解，不是配图

同一句字幕"TCP 连接要先握三次手"，可以配两种画面。

**配图版**：左右两个方框，标着"客户端"和"服务器"，中间来回三根箭头，写着 SYN、SYN+ACK、ACK。
每个元素都没错，可观众看完只记得三根箭头，说不出为什么是三次、少一次会怎样。这三根箭头换到任何一段讲"通信"的文案里都成立。

**讲解版**：两个人打电话。"喂，听得到吗？""听得到，你听得到我吗？""听得到。"三句话说完，才开始聊正事。
然后让它坏一次：只说两句就开聊，一通早就挂断的旧电话突然接通了，对面以为有人找他，拿着话筒傻等。
观众看完能讲出"因为双方都要确认对方能听、也能说，所以要三次"。

区别只有一个：讲解版屏上的东西叫得出名字，句子里的动作真的发生了，而且换一段文案就不成立。

## 二、六种演法

一句字幕出来，屏上能做的事归结起来是六种。分镜表里每一句都标一种。

1. **先让观众试。** 屏上摆一个东西，让观众自己先起反应；字幕晚半拍，说出观众脑子里刚发生的事。
   例：屏上一本一千页、没有目录的书，问"锁"字在第几页。观众本能地想从头翻，字幕才说"这就是全表扫描"。开头和一切"你以为……"的地方用它。
2. **照句子演。** 句子里说到什么，屏上就是什么；句子里的动词，屏上真的发生。
   例："数据包从你家路由器出发"，屏上一个小信封真的从一台路由器里出来。讲故事、举例子、摆事实用它。人只画剪影、背影或者一只手。
3. **当场跑一遍。** 拿一个最小的具体题目，把方法一步一步走完，角上挂着状态和计数。字幕只用人话说规则，说完就让过程自己跑。
   例：在 1000 页里找一页，每次翻到中间、排除一半，真的翻十次，角上"第 N 次 / 还剩 N 页"在跳。讲方法、机制、"为什么一定是这样"用它。数是真算出来的。
4. **左右对照。** 两样东西放进同一个版式，只留一处不同。
   例：数组和链表各插入一个数，左边一整排往后挪，右边只改了两根线。凡是"A 比 B"都用它。
5. **放进一张图。** 把前面已经出场的东西摆进一张坐标图，轴用人话写，重点是图上的一块区域或一条线。
   例：数据量越来越大，"一页页翻"和"每次排除一半"两条线越分越开。只在回答"为什么"时用，而且一定排在例子后面。
6. **只给字。** 规则、名字、结论、引文；或者什么都不加，把上一幕停住。

另有两个贯穿全片的动作，不算新演法：
**回到原处**：前面的道具、尺子、开场画面再出现一次，只改一处。
**两头合一**：把比喻的两头放进同一个画面。例：讲缓存时，书桌上摊着几本常用的书，书脊上印着的就是内存地址。

## 三、每类句子怎么演，什么时候不画

能画的尽量画。但大约每五句里，会有一句不配新画面：那些句子后面的停顿，是观众把刚看到的东西想明白的时间。
拿不准一句该怎么演，就在这张表里找最像的一行：

| 这句话在做什么 | 怎么演 | 例子 |
|---|---|---|
| 讲一件事、举一个例子 | 照句子演 | 一个小信封从路由器出门，经过三个路口 |
| 讲一个方法、一个机制 | 当场跑一遍，角上挂着状态 | 二分查找：每次翻到中间，"还剩 N 页"在跳 |
| 说观众自己的直觉 | 先让观众试 | 先给一本没目录的厚书，问"锁"字在哪 |
| 比较两样东西 | 左右对照：版式一样，只差一处 | 数组和链表各插入一个数 |
| 说一个数量 | 让它数得出来：逐格亮、从 0 数上去，或者一把全片通用的尺子；不是给数字配一根柱子 | 读一次磁盘约 10 毫秒：同一把尺子上，读内存那一格细得几乎看不见 |
| 个别随机、整体有规律 | 让成百上千个小东西真的落下来，堆出形状 | 一千个键落进哈希表的桶里，桶差不多一样高 |
| 越来越接近 | 一条实时折线 + 一条目标虚线 + 一个在跳的计数 | 抛硬币的次数越多，正面的比例越贴近一半 |
| 有多少种可能 | 画成一棵树，在叶子上数 | 三位二进制：分叉三次，八片叶子 |
| 谁包含谁 | 一个圈在另一个圈里 | 进程里装着几个线程 |
| 互相等、停不下来 | 两个东西在原地来回张望，越来越急 | 死锁：两个人各拿一把钥匙，等对方先给 |
| 从这里到那里 | 一张简化的地图，一个东西沿线走过去 | 数据包从北京到旧金山 |
| 很远、很久、很多 | 一条线，光点一格格走，旁边标数 | 光从地球到月球要 1.3 秒 |
| 关于文字、代码 | 让字自己演：逐字打出、高亮、划掉、换位置 | 一行 SQL 被拆成"找哪张表、要哪几列、按什么筛" |
| 总结"为什么会这样" | 放进一张图，用前面出现过的东西摆 | 数据量和翻页次数：两条线越分越开 |
| 落到"你"身上 | 两头合一 | 你的手机屏幕上，正好是刚才那个小信封 |
| 提问 | 不加新画面：停住上一幕，或者只留一个问号 | — |
| 起名字、下定义 | 只给字，前面的道具围在旁边 | 大字"索引"，那本书和目录在旁边 |
| 规则、结论 | 只给字，或者把上一幕停住 | — |
| 引一句原话 | 原文 + 译文 + 出处 | — |
| 某年、某人 | 一行小字贴在已有的画面上；不为它换场，不画脸 | — |
| 过渡句 | 不画，让下一幕直接进场 | — |
| 该怎么做 | 一步一个具体动作；顶上的步骤标签逐个点亮 | 1/3 建索引 · 2/3 看执行计划 · 3/3 再查一次 |
| 回顾 | 前面每段缩成一个小图标排成一排，一句亮一个 | — |

找不到对应的一行，多半说明这句话既不能数、不能比，也不能演，是一句该删的议论。

几条容易犯的：

- **刚演过的事，结论句不要再画一遍。** 把画面停住就够了；再配一张图，等于不相信刚才那一幕。
- **没有东西可指的句子，不要硬配图。** 硬配出来的就是光点、连线和抽象图形。
- **一个数能说清的，不画图表。** 要画，就画成数得出来的东西，并且和另一个数放在同一个画面里比。
- **公式不单独解释。** 把它贴在刚演过的例子旁边，每个符号对得上屏上的某样东西，再加一句人话。
- **一个场景撑 2–5 句字幕，每句只改一处。** 不是每句话换一个新画面。

## 四、怎么给概念找形象

对概念清单里的每一个，按顺序问。前面的问题有答案，就不往后问。

1. **它本身是个看得见的东西吗？** 是，就画它本身：硬盘、网线、路由器、内存条。要一眼认得出。
2. **它是一个过程或方法吗？** 找一个小到能把每一步都画出来的题目，走一遍：8 个数的排序、一次握手、一条 SQL 的执行。
3. **它是一个量、一种程度吗？** 给它一把尺子，用同一把尺子量三样东西。
4. **它是观众脑子里的事吗？** 设计一个五秒钟的小测试，让它当场发生。
5. **它是一条规律吗？** 先画两三个例子，再把例子摆进一张图。
6. **都不是**（一个判断、一种态度、一句总结）：不画，只给字。

看不见的东西（数据、进程、锁、事务）最难。办法是借一样生活里的东西来演它，而且这样东西要带着它最关键的性质：
锁画成柜门上的一把挂锁，抢不到钥匙的人只能在门外排队；缓存画成书桌，常用的书摊在桌上，不常用的放回书架。
比喻选好以后，全片都用它，不中途换。

找到以后，再问三个问题，把形象做强：

- **观众在生活里哪儿见过它？** 找到那个锚，概念才记得住。
- **拉近或拉远一级，是什么样？** 原因和结果常常就在相邻的两个尺度上：一行数据、一页、一棵树、一块磁盘。
- **它坏了会怎样？** 让它错一次。东西正常的时候看不出它在干活，坏了才看得出。

### 画得像它本身

- **有体积，有材质。** 硬盘有金属的光泽和转动的盘片；书有书脊和页边。一个方框加一个标签"硬盘"，不算画了硬盘。
- **从认得的地方进场。** 先给一个人人见过的画面，再推进去找要讲的东西：从电脑主机推进去，才到内存条上的一格。
  把一格内存直接摆在空白背景上，观众不知道它在哪、有多大、跟自己有什么关系。
- **记号只当说明。** 箭头、虚线框、小圆点可以贴在东西旁边，不能自己当主体。
- **实心的东西画在底层。** 有体积的东西用 `f.under()` 画，不让辉光把它冲白（见 `engine.md`）。

### 每一镜过三问

- **屏上这是什么？** 用一个日常的词回答，遮住字幕和标签也看得出来。答案是"一些点""几条线""几个方框"的不合格，除非它是一件带刻度、叫得出名字的仪器。
- **它在干什么？** 用一个动词回答，就是字幕里的那个动词，或者它的直接后果。
- **观众因此明白了什么？** 一句话，而且和上一镜明白的不一样。

## 五、分镜表

先写分镜表，再建工程。文案和画面一起写：句子里没有东西可画，就改句子，而不是硬配图。

表前写清：一句话论点；全片的那个形象；那把尺子；外观卡在 `look.md`；哪几镜是同一个画面。

| # | 时间 | 字幕 | 演法 | 屏上是什么，在干什么 | 小字 | 观众明白了什么 | 声音 |
|---|---|---|---|---|---|---|---|

- 时间写起止秒数；片名、纯画面的段落也占一行，字幕写"（无）"。
- 字幕里 `{词}` 染强调色，`{!词}` 染警示色，一句最多一处。
- 演法填第二节六种之一，或者"停住""回到原处""两头合一"。
- "屏上是什么"用日常的词；"在干什么"用一个动词。
- 小字是给这一句的证据：数字、名字、出处。一镜最多一条。
- 声音只填关键的那一下，大多数行空着。

表后写清：屏上每个数是怎么来的；哪些是示意；用 `scripts/estimate.py` 估出来的时长。

写完自己查：

- 遮住字幕一列，只读"屏上是什么，在干什么"，看得出在讲什么吗？
- "只给字 / 停住 / 提问不画"大约占五分之一吗？一个都没有，是把结论也画了；占了一半，是没找到形象。
- 有没有哪一镜换给别的文案也成立？
- 每个场景撑了两句以上、每句只改一处吗？
- 每 20–30 秒有一段画面自己演、没有字幕的时间吗？全片的形象出场三次以上吗？
- 让人"哦——"的那一下在第几镜？它之前有铺垫、之后停得住吗？

### 例子：《索引为什么快》开头 30 秒

论点：索引把"一页页翻"变成"每次排除一半"，所以数据再多，也只要翻几次。
形象：一本很厚的书，和它最前面的目录。尺子：右上角"翻了几页"的计数。
外观卡：暗场，冷色；强调色金色表示"找到了"，警示色红色表示"白翻的"。

| # | 时间 | 字幕 | 演法 | 屏上是什么，在干什么 | 小字 | 观众明白了什么 | 声音 |
|---|---|---|---|---|---|---|---|
| 1 | 0.5–4.5 | 一本一千页的书，"锁"字在哪一页？ | 先让观众试 | 一本厚书落在桌上，镜头推近书脊 | 1000 页 | 要在很多页里找一样东西 | thud |
| 2 | 5.0–9.5 | 没有目录，只能一页一页翻。 | 当场跑一遍 | 书页飞快地翻，翻过的页角变红，右上计数从 0 跳到 612 | 翻了 612 页 | 没目录要翻很多页 | |
| 3 | 10.0–13.0 | 运气不好，{!一千页}全要翻完。 | 照句子演 | 计数跳到 1000，整本书的页边都红了 | | 最坏要全翻一遍 | |
| 4 | 13.5–16.0 | 有没有更快的办法？ | 提问，不画 | 画面停住，红色的页边慢慢暗下去 | | （悬念） | |
| 5 | 16.5–21.0 | 翻开目录，先看中间那一行。 | 当场跑一遍 | 书合上，翻到最前面的目录；目录页正中一行亮起 | | 目录能直接跳 | |
| 6 | 21.5–26.5 | 每看一次，就排除一半。 | 当场跑一遍 | 一半的页盖上暗块，镜头推到剩下的一半，再排除一半；计数 1、2、3…… | 还剩 500、250、125…… | 每次少一半 | |
| 7 | 27.0–30.0 | 第 {10} 次，就找到了。 | 照句子演 | 计数停在 10，那一页亮起金色，"锁"字在页中间 | 2¹⁰ = 1024 > 1000 | 十次就够 | reveal |

数的来历：1000 页每次排除一半，第 10 次时剩下不到 1 页（2 的 10 次方是 1024）。612 是随机演示的一次。
示意：真实的数据库索引是一棵多叉的树，一次排除的远不止一半；这里用"每次一半"讲清楚道理，片尾小字写明"示意"。
时长：7 句，每句约 4 秒，30 秒左右。
