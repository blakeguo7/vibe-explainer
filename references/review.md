# 质检：看图改图和终检

第一次渲出来的画面几乎都有毛病。这种片子是看着图改出来的，不是写完代码就完了。
这一份是改图时对照的东西：第一节三问，第二节毛病表，第三节终检表，第四节让程序查的部分。

## 一、三问

遮住字幕和小字，对每一镜问：

- **这是什么？** 用一个日常的词回答。
- **它在干什么？** 用一个动词回答，就是字幕里的那个动词。
- **我明白了什么？** 一句话，和上一镜不一样。

答得含糊，就是没做好。看的是截图，不是代码："代码应该没问题"不算数。

怎么截图看：

```bash
python engine/render.py <工程目录> --sheet 16          # 全片均匀 16 帧拼一张，看全局
python engine/render.py <工程目录> --stills 5.2 18     # 原尺寸截几帧，看细节
python engine/render.py <工程目录> --motion 8 10.5     # 一段时间里取 12 帧拼一张，看转场说不说得清
```

每一轮：把看到的毛病列出来，改，重截同样的时刻，确认改掉了、没改坏别的。至少改两轮再给用户看。

## 二、毛病表

| 看到的毛病 | 多半因为 | 怎么改 |
|---|---|---|
| 主体缩在中间小小一团 | 尺寸是按"画得下"定的 | 先定屏幕上的大小：主体占画面宽度六成以上，最小的单元（一个字、一颗珠子）不小于 20 像素，再反推排法 |
| 遮住字幕认不出是什么 | 画成了记号 | 加体积和材质；或者从一个认得的画面推进去；还不行，回去换形象 |
| 字幕里说到的东西屏上没有 | 分镜时漏了这个名词 | 画出来，或者改句子；开场最容易漏 |
| 一大片发白、发糊 | 实心的大色块吃了辉光 | 用 `f.under()` 画到底层；或者这一段把 `f.bloom` 调低 |
| 渐变一圈一圈的硬边 | 用很多层半透明叠出软边 | 改用 `f.rgrad()` 径向渐变 |
| 闪一下，整幅发黄、发脏 | 闪光用了强调色：彩色的光加在深底上，整幅偏色变浑，强调色也被铺满了全屏 | `f.flash` 用白色（不写 `color` 就是白），亮度从 `peak: .2` 左右试起；强调色只留给那一个东西 |
| 东西是平的，像贴纸 | 没有明暗 | 边缘压暗一点，左上加一道高光，背后垫一层淡影 |
| 线压在东西上面 | 线画在内容层，东西画在底层 | 线也画进底层、先画线再画东西，或者把线头收在东西的边上 |
| 小字压在主体上读不清 | 标注放得太近 | 拉到主体外面，用一根细线连过去；一镜最多一条小字 |
| 东西伸进了字幕区 | 推近以后边缘被带了进来 | 在字幕区以上收住，或者推近时一起暗下去（`--check` 会报出时间） |
| 字幕压在亮底上看不清 | 背景太亮 | 这一段把背景压暗；或者在外观卡里给字幕加底板（`subs.plate`） |
| 一句字幕里画面变了三四处 | 贪多 | 拆成两句，或者删掉次要的 |
| 连着几句画面没变 | 没给每句找到那"一处变化" | 回分镜表，每句写清改哪一处 |
| 转场中间几帧说不清在干什么 | 两个状态之间直接插值 | 换成一个叫得出名字的动作（推进去、翻过去、落下来）；或者压到半秒以内 |
| 推拉镜头先平移、后猛冲 | 缩放是线性变化的 | 用 `VE.zoom` 让缩放在对数里走 |
| 第一秒就是片名 | 没有钩子 | 先用几秒演一个东西、问出问题，再出片名 |
| 片名看不出讲什么 | 拿全片的比喻或意象当了片名 | 改成内容本身：讲 MySQL 架构就叫"MySQL 架构"；比喻留在片子里演 |
| 图表是静止的 | 没让它真的算 | 从第 1 次画到第 N 次，计数跟着跳，停在算出来的那个数 |
| 字幕弹出来，东西进场都弹一下 | 套了现成的入场动画 | 字原地显影，线是画出来的，数是数上去的；只有真的东西落地才弹 |
| 各段各画各的，像几条片拼的 | 没定全片的那个形象 | 回到找形象那一步，定一个形象、一把尺子，各段都用它来演 |
| 结尾是一段总结 | 不相信前面的画面 | 回到开场的画面，只改一处；最后一句回扣主题 |
| 缩到手机大小，字读不清 | 字号按电脑屏幕定的 | 字幕 40 像素以上，标注 20 像素以上，再小的删掉 |
| 字幕读起来像口播稿 | 删了语气词就当字幕用 | 删掉"我们""其实""那么"；一句拆成两句，每句一个动作 |
| 音效太多，或者冒出了长音 | 声音按"填满"在配 | 只给关键的那几下，一镜最多一声 |
| 成片和外观卡对不上 | 写代码时随手改了颜色或字号 | 以外观卡为准；要改，先改卡 |

## 三、终检表

整片渲出来以后，先静音、遮住字幕看一遍：每一段在讲什么，看得出来吗？再只读字幕一遍：通顺吗？句子里的名词屏上都找得到吗？最后逐行对这张表：

| | 门槛 |
|---|---|
| 讲解 | 成片和分镜表对得上；抽五镜过三问都答得出；没有只是配图的画面；尺子和道具回过场 |
| 画与不画 | 提问、命名、结论没有硬配图；也没有连着几句画面不变 |
| 结构 | 片名就是讲的内容；片名在钩子之后出现；结尾回到开头的画面；最后一屏是片名和出处 |
| 外观 | 成片和外观卡对得上；每种颜色全片一个意思；字幕区只有字幕 |
| 字幕 | 每句一行；一句最多染一处颜色；读得完（`--check` 会查） |
| 节奏 | 没有硬切；主体出完之后停住让人读；每 20–30 秒一段没有字幕的纯画面 |
| 声音 | 只有音效，只在关键的那几下；提问、命名、结论不出声 |
| 事实 | 屏上每个数字和事实表一致；每个概念有出处；示意的地方写明了 |
| 技术 | `--check` 全部通过；画面尺寸和外观卡一致；没有水印和署名 |

不合格的时间点列出来，改完只重渲那一段（`--clip`）确认，再渲全片。
交片时说实话：还不满意的地方、没做的东西、没完整看过的部分，直接列出来。

## 四、让程序查的

人眼容易漏的，交给 `render.py --check`。它会查：

- **同一帧渲两次一不一样。** 不一样，说明用了 `Math.random()`、`Date.now()` 或者跨帧保存的状态，分段渲染时画面会对不上。
- **每句字幕会不会太宽。** 超出左右边距的会报出来。
- **每句字幕读不读得完。** 停留不到 1.2 秒，或者每秒要读 7 个字以上，会报出来；两句字幕时间叠在一起也会报。
- **字幕区有没有被画面占用。** 每半秒查一次，报出被占的时间段。

`--check` 没报问题，不等于片子好：它只查得了这几样，讲得清不清楚，还是要靠第一节的三问。
