# 字幕：给人"读"的文案

没有旁白，文案就是字幕。它不是口播稿删掉语气词，而是另一种文体：每句话都要配得上一个屏上动作，
而且短到观众一眼读完，还有余力看画面。

## 一、时长怎么估

时长不预设，是从分镜表算出来的：

```bash
python scripts/estimate.py <工程目录> --hold 4
```

它数分镜表里有字幕的句子，再按每句停留的秒数估出全片多长。每句停多久，看外观卡里的字幕节奏：
一行中文、逐字亮起的约 3 秒；整行淡入的约 4 秒；带一行英文的约 5 秒。
估的时候要算上没有字幕的时间：片名、转场、让画面自己演的段落，大约占全片三成。

**句数从哪来**：一个概念演透，通常要 3–10 句：一个例子、一次当场跑一遍、一句命名或结论。概念几个、每个几句，分镜表写完就知道了。

**结构跟着长度走**：

| 算出来的长度 | 结构 |
|---|---|
| 一分钟以内 | 只讲一件事：钩子，一个实验从头演到尾，命名，回到开头。片名卡缩到 2–4 秒 |
| 一到四分钟 | 钩子、片名、三到五站、落到"你"身上、回到开头 |
| 四分钟以上 | 分章，每章一个小实验，角上挂章节标；代码按章拆文件 |

**两件不做的事**：不为凑时长加内容；不为压时长把一个道理塞进几句话。
算出来比预想的长很多时，问用户：要一条长片，还是拆成几集。

**几个固定的节奏**：钩子 6–20 秒（一分钟以内的片子可以更短）；每 20–30 秒留一段没有字幕、画面自己演的时间；结尾回到开头的画面。

## 二、几种结构

骨架都一样：

```
钩子        先演一个具体的小东西，末尾抛一个问题，或者对"你"说一句话
片名        讲什么就叫什么（"MySQL 架构"）+ 一句人话的副题
主体        几站由内容定，每站一个画面装置
落到"你"    把全片的概念放到观众自己的生活里
回到开头    开场的画面再出现，只改一处；最后一句回扣主题
片尾        片名 + 出处
```

主体按题目选一种排法：

**一件事**（一分钟以内）。一个实验从头到尾发生一遍：先让观众看见现象，再让它坏一次，最后命名。
例：《三次握手》，打电话的两句和三句，各演一次。

**拆零件**（一个系统怎么运转）。顺着一样东西在系统里走的路线，一站一个零件：每站只讲"它在这里被做了什么"。
例：一条 SQL 从敲下回车到拿到结果：连接、解析、优化、执行、存储。全片跟着同一条 SQL 走，它就是那个形象。

**一路追问**（一个机制为什么是这样）。每站回答上一站留下的问题：为什么要缓存？因为磁盘慢。那缓存满了怎么办？要扔掉一些。扔哪些？……
每个问题都配一个当场跑一遍的小实验，最后一站回答最开始的那个问题。

**从前到后**（一样东西怎么演变来的）。每站是"年份 + 当时的问题 + 当时的办法 + 留下的毛病"，下一站解决上一站的毛病。
要有一条悬着的线：开头抛出一个问题，中间几站都没完全解决，最后一站才解掉。没有这条线，就成了流水账。

不管哪种，**全片只用一个比喻**。它在钩子里出现，是一个看得见的东西，后面每一段都能用它造句。
例：讲缓存全片都是"书桌和书架"：命中是"书就在桌上"，淘汰是"把最久没翻的放回书架"。观众不用记住术语，也能复述整条片。

## 三、句式

下面几种句子最常用。不必凑齐，但钩子句、论点句和最后一句，要从这里挑。

1. **前半句给直觉，后半句翻过来。** 
   - 一页页翻，书越厚越慢；/ 有了目录，再厚也只翻几次。
   - 内存比磁盘快十万倍，/ 可它一断电，什么都不剩。
2. **破折号后面才是答案。** 术语和数字放在破折号之后，画面在破折号那一刻揭晓。
   - 每看一次，就排除一半——这就是二分查找。
   - 一千页的书，最多翻十次——因为 2 的 10 次方是 1024。
3. **问句。** 每四到六句一个，问完下一句画面就去答。
   - 有没有更快的办法？／少握一次手，会怎样？
4. **一句话写一个人。** 不写生平，只写一个让这个人显得真实的细节。
   - 他嫌每次都从头找太慢，在书前面加了一页目录。
5. **"不是……是……"只留给论点。** 全片一到三句，通常是最后一句。
   - 快，不是因为翻得快，是因为不用翻。
6. **直接对"你"说。** 钩子末尾一句，结尾一到两句。
   - 你每天打开的网页，背后都在找这本书里的一页。
7. **数字具体到能上屏。** 10 毫秒、1024、十万倍。写"很多""很快"的地方，回去查出那个数。
8. **最后一句回扣主题。** 用全片的那个形象，把片名讲的东西收成一句。
   - 《MySQL 索引》→ 用得上目录，两千万行也只翻三页。

不写的东西：寒暄和预告（"今天我们来聊""让我们一起"）、总结腔（"这告诉我们""综上所述"）、形容词堆叠、"众所周知""值得一提的是"。
句子是陈述句，主语是具体的人和东西。一行放不下就是太长：横屏中文一般不超过 22 个字，竖屏不超过 16 个字（`--check` 会量宽度）。

## 四、从笔记改写成字幕

学习笔记是给人查的，字幕是给人看着画面读的。从笔记改的时候：

- **先挑，后写。** 笔记里十个知识点，片子里讲三个讲透的，比十个都点到强。挑那些"有一个画面能演出来"的。
- **定义往后挪。** 笔记通常先写定义；字幕先给例子，定义放在观众看过例子之后。
- **长句拆短。** 笔记里一句话常常带三个从句；字幕一句只讲一件事，一句配一个动作。
- **补上"为什么"。** 笔记常常只写结论（"索引用 B+ 树"），字幕要让观众看见为什么（"一次翻开一页能排除几百个"）。
- **删掉只有考试用得上的细节。** 片子是建立直觉的；细节留在笔记里。

## 五、事实和片名

- 每一站至少一个可核对的锚：年份、人名、数字、出处。站与站之间的因果也要查。
- 屏上给出处：书名或论文写"作者，年份"；示意图标"示意"；拿不准的写"一种说法"。
- 片尾一屏出处，三到四行小字。拿不准的事实，宁可换一个拿得准的例子。
- **片名** 就是这条片讲的内容，讲什么就叫什么：MySQL 架构、MySQL 索引、TCP 三次握手、缓存。
  不另起比喻、意象或者打哑谜的名字：讲 MySQL 架构的片子不叫《两层楼》，讲索引的不叫《三页》。
  观众在一排视频里找东西、回头复习，看的都是片名；它得一眼说清讲什么。比喻是拿来讲明白的，放在片子里演，不放在片名上。
- **副题** 一句人话，说清看完能得到什么：为什么快 / 为什么偏偏是三次。不重复片名里的词：片名是"MySQL 索引"，副题写"为什么快，又为什么会失灵"。
- **外文行**（可选）：英文大写小字，比如 INDEX · WHY IT'S FAST。
